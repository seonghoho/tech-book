# "36만 9천 원"을 "9천 원"으로 칠하던 정규식

## 증상

정부·지자체 지원 사업을 정리하는 블로그를 따로 운영하고 있습니다. 사업마다 요약문이 있고, 요약문에서 받을 수 있는 금액과 마감일에 형광펜을 칠해 눈에 띄게 합니다.

그런데 "월 36만 9천 원 지급" 같은 문장에서 "9천 원"에만 형광펜이 칠해졌습니다. 읽는 사람은 지원금이 9천 원이라고 보게 되고, 코드가 계산한 금액 값도 9,000이었습니다.

## 원래 정규식

금액을 찾는 정규식은 이랬습니다.

```ts
const UNIT: Record<string, number> = { "": 1, 천: 1_000, 만: 10_000, 억: 100_000_000 };
const MONEY_RE = /(\d[\d,]*(?:\.\d+)?)\s*(천|만|억)?\s*원/g;
```

숫자 하나, 단위 하나(없어도 됨), 그리고 "원"입니다. "300만 원", "295,200원", "1.5만 원"처럼 숫자와 단위가 한 번만 나오는 금액은 잘 잡습니다.

"36만 9천 원"은 숫자와 단위 묶음이 두 개입니다. 정규식은 왼쪽부터 맞춰 보는데, "36만" 다음에 "원"이 아니라 " 9"가 와서 첫 시도는 실패합니다. 그다음 위치에서 다시 시작해 "9천 원"을 찾고, 거기서 매치가 끝납니다. 앞의 "36만"은 버려집니다.

## 고친 방법

### 1. 억·만 조각을 앞에 여러 개 허용한다

```ts
const MONEY_RE =
  /(?:\d[\d,]*(?:\.\d+)?\s*(?:억|만)\s*)*\d[\d,]*(?:\.\d+)?\s*(?:천|만|억)?\s*원/g;
```

앞부분 `(?:숫자 (억|만) 공백?)*`이 "1억 ", "36만 " 같은 큰 단위 조각을 0개 이상 받습니다. 그 뒤는 원래 정규식과 같습니다. `*`는 기본적으로 탐욕적(greedy)이라 앞 조각을 가능한 한 많이 붙잡습니다. 그래서 "36만 9천 원" 전체가 한 매치가 됩니다.

앞 조각을 억과 만으로만 제한한 데는 이유가 있습니다. 한글 맞춤법 제44항은 수를 '만' 단위로 띄어 쓰게 합니다("12억 3456만 7898"). 금액을 이렇게 쓰면 억과 만 뒤에서 끊기고 마지막 조각에만 천이나 숫자가 남습니다. 정규식도 그 모양을 그대로 따랐습니다.

### 2. 값은 조각별로 더한다

캡처 그룹 하나로는 값을 구할 수 없어서, 매치된 문자열을 다시 조각으로 나눠 더하게 했습니다.

```ts
const MONEY_PART_RE = /(\d[\d,]*(?:\.\d+)?)\s*(천|만|억)?/g;

function moneyValue(text: string): number {
  let sum = 0;
  for (const p of text.matchAll(MONEY_PART_RE)) {
    sum += Number(p[1].replace(/,/g, "")) * UNIT[p[2] ?? ""];
  }
  return sum;
}
```

"36만 9천 원"은 `36 × 10,000 + 9 × 1,000 = 369,000`이 됩니다.

## 같은 문장에 돌려 본 결과

이 글을 쓰면서 예전 정규식과 지금 정규식을 같은 문장들에 다시 돌려 봤습니다.

| 문장 | 예전 정규식 | 지금 정규식 |
|---|---|---|
| 월 36만 9천 원 지급 | "9천 원" = 9,000 | "36만 9천 원" = 369,000 |
| 1억 2,000만 원 지원 | "2,000만 원" = 20,000,000 | "1억 2,000만 원" = 120,000,000 |
| 3만5천원 | "5천원" = 5,000 | "3만5천원" = 35,000 |
| 최대 300만 원 | "300만 원" = 3,000,000 | 같음 |
| 295,200원 | "295,200원" = 295,200 | 같음 |
| 1.5만 원 | "1.5만 원" = 15,000 | 같음 |
| 12만원씩 3회 | "12만원" = 120,000 | 같음 |
| 3천만 원 대출 | 매치 없음 | 매치 없음 |
| 2천5백만 원 | 매치 없음 | 매치 없음 |

단위가 하나뿐인 금액은 결과가 그대로이고, 여러 조각으로 된 금액만 달라졌습니다. 띄어 쓰지 않은 "3만5천원"도 `\s*`가 공백 없음을 허용해서 함께 잡힙니다.

## 남은 문제: "3천만 원"

표의 마지막 두 줄처럼 "3천만 원", "2천5백만 원"은 예전에도 지금도 잡지 못합니다. 이 정규식은 단위를 숫자 하나에 하나씩만 붙인다고 가정합니다. "3천만"은 "3"에 "천"과 "만"이 겹쳐 붙은 형태라 그 가정에 맞지 않습니다.

블로그의 사업 데이터 파일에서 "N천만 원" 꼴을 세어 보니 129번 나왔습니다. 대부분 "연소득 5천만 원 이하" 같은 소득·재산 기준이었습니다. 이런 문장은 받는 금액이 아니라서 형광펜이 원래 건너뛰도록 되어 있어, 지금 화면에는 차이가 없습니다. 다만 받는 금액으로 "최대 3천만 원"이 나오는 사업이 들어오면 그대로 놓치게 됩니다.

고치려면 한 조각 안에서 천·백과 만·억이 겹치는 경우를 받아야 합니다. 정규식을 늘리는 방법과 표기를 먼저 숫자로 바꾸는 방법이 있고, 둘의 차이는 다음 절에 정리했습니다.

## 다른 방법

| 방법 | 장점 | 단점 |
|---|---|---|
| 정규식에 조각을 이어 붙인다 (이번 방법) | 바꾸는 코드가 적고, 형광펜 위치(문자열 인덱스)를 그대로 쓸 수 있다 | "3천만"처럼 단위가 겹치는 표기는 정규식이 빠르게 복잡해진다 |
| 금액 표기를 먼저 숫자로 바꾼 뒤 찾는다 | 단위가 겹치는 표기도 규칙으로 풀 수 있다 | 바꾼 문자열과 원문의 위치가 달라져, 형광펜 위치를 원문에 다시 맞춰야 한다 |
| 금액을 데이터에 따로 저장한다 | 표기와 상관없이 정확한 값을 쓴다 | 요약문을 쓸 때마다 금액 필드도 따로 채워야 한다 |

형광펜은 매치의 시작과 끝 위치(`index`, `end`)로 원문을 칠합니다. 정규식 방식은 이 위치를 매치에서 바로 얻을 수 있고, 숫자로 바꾸는 방식은 위치를 원문 기준으로 다시 계산하는 단계가 하나 더 필요합니다.

## 비슷한 문제를 알아보는 법

- 형광펜이나 링크가 단어의 뒷부분에만 걸린다
- 계산된 값이 실제 값보다 한두 자릿수 작다
- 정규식에 "숫자 + 단위" 묶음이 한 번만 들어 있다
- 테스트 문장이 "300만 원"처럼 단위가 하나뿐인 경우만 있다

금액을 다루는 정규식이라면 "36만 9천 원", "1억 2,000만 원", "3만5천원", "3천만 원"을 테스트 문장에 넣어 두면 이런 경우를 미리 확인할 수 있습니다.

한국어 표기나 한국 시간 때문에 생긴 다른 문제는 [오전 9시 전에만 달력에서 어제를 고를 수 있던 이유](/posts/frontend-troubleshooting/today-before-9am-kst)에도 정리했습니다.
