# 관리자 글쓰기 화면 설계

## 목표

코드 커밋 기반 글쓰기가 발행을 미루게 만드는 문제를 없앤다. AdSense 재심사에 필요한 "주 1~2회 꾸준한 발행"을 운영 가능하게 만드는 것이 목적이다. 사용자는 1명이고, 모바일에서도 쓸 수 있어야 한다.

## 결정

| 항목 | 선택 | 이유 / 대안 |
|---|---|---|
| 저장소 | git 마크다운 그대로 (DB 없음) | 코드 기반 작성과 100% 호환되고, 이력과 롤백이 무료다. Headless CMS나 DB는 원본을 둘로 나눈다. |
| 인증 | GitHub OAuth를 직접 구현 + HMAC 서명 쿠키 | next-auth v5는 beta이고 Next 16 호환성 리스크가 있다. 1인 allowlist만 필요해서 100줄 내외로 충분하다. 비밀번호 방식은 관리할 비밀이 늘어난다. |
| 커밋 토큰 | 서버의 fine-grained PAT (이 저장소 Contents만) | OAuth 토큰에 `repo` scope를 받으면 모든 저장소 권한이 생긴다. |
| 커밋 방식 | Git Data API (blobs → tree → commit → ref) | 초안 삭제와 posts 생성을 커밋 하나로 원자적으로 처리한다. Contents API는 파일 1개 = 커밋 1개다. |
| 초안 위치 | master의 `src/content/drafts/` | 사용자 결정(저장소에 커밋). 별도 브랜치는 master와 갈라져 관리가 어렵다. 배포 낭비는 Ignored Build Step으로 막는다. |
| 목록 조회 | GitHub GraphQL 1회 | 배포본 fs는 마지막 배포 시점의 상태라 초안이 보이지 않는다. REST로는 파일 수만큼 요청해야 한다. |
| 예약 발행 | `isPublished()` 필터 + 일일 cron 재배포(공개 대상이 있을 때만) | 정적 생성 페이지, 사이트맵, RSS를 한 번에 갱신하는 가장 단순한 방법이다. ISR만으로는 `generateStaticParams`와 posts.json이 갱신되지 않는다. |
| 미리보기 | 글 상세와 같은 `renderMarkdownToHtml` + 같은 prose 클래스 | 미리보기와 실제 화면이 어긋나지 않게 한다. |
| 이미지 | 클라이언트에서 1600px webp로 축소 후 즉시 커밋 | 휴대폰 원본(수 MB)이 저장소를 키우지 않게 한다. Vercel 요청 4.5MB 한도도 지킨다. |
| 품질 체크 | 경고만, 차단 없음 | AdSense 제안서의 기준(1,500자, 내부 링크 등)을 습관화하되 작성 흐름은 막지 않는다. |
| 발행 글 수정 | slug, category, date 고정 + `updated` 자동 갱신 | 게시일 정책과 URL 안정성(색인, 외부 링크)을 지킨다. |

## 범위 밖

- 여러 명 사용, 협업 편집, WYSIWYG, 게임 콘텐츠 편집
- AI 초안 생성. 대량 생성 콘텐츠 정책 리스크 때문에 의도적으로 넣지 않는다.

## 알려진 한계 / 향후

- 저장소가 public이라 초안이 공개된다(docs/admin-editor.md 경고 참고).
- 초안 단계에서 slug를 바꾸면 이미 올린 이미지는 이전 slug 폴더에 남는다. 마크다운 경로는 그대로 유효하다.
- 예약 공개 정밀도는 하루 단위(KST 0시 이후 첫 cron 실행)다. Hobby 플랜 cron은 지정한 시각 이후 1시간 안에 실행된다.
- 초안 저장은 수동 버튼이다. 자동 커밋은 커밋 이력을 어지럽혀서 넣지 않았고, 대신 브라우저 자동 백업을 둔다.
