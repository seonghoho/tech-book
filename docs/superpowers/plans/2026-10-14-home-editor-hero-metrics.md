## 메모

- 처음 측정(H1 `font-bold`)에서는 LCP 중앙값 18,611ms로 오히려 느려졌다. 홈이 원래 쓰지 않던 Pretendard Bold(773KB woff2)를 H1 때문에 새로 받았기 때문이다. H1을 이미 쓰는 600(semibold)으로 바꿔 폰트 요청을 4개 → 3개로 줄였다.
- LCP·FCP 모두 렌더 지연(render delay)이 대부분이고, 원인은 굵기당 약 760KB인 Pretendard 전체 글리프 woff2다. 폰트 서브셋(dynamic subset) 적용이 다음으로 효과가 큰 개선이다.
- LCP 요소는 H1이 아니라 같은 영역의 소개 문단이다(화면 면적이 더 크다). 둘 다 텍스트라 이미지 로딩 의존은 없다.
- 본문 글자 수는 1,377 → 1,658자로 늘었지만 명세 목표(2,000자)에는 못 미친다.
- 에디터 청크(`editor-hero-intro-played` 포함) gzip 5,206B — 예산 8KB 이내.
- 홈 HTML: `<h1>` 1개, `adsbygoogle.js` 있음, SSR에 도형 4개 포함.

## Pretendard dynamic subset 적용 (2026-10-15)

같은 조건(로컬 `next start -p 5175`, Lighthouse 12.8.2 모바일 시뮬레이션 스로틀링, 홈 3회).
전체 글리프 woff2(굵기당 약 770KB) 4개를 공식 dynamic subset(굵기당 92조각, unicode-range)으로 바꿨다.

| 측정 | LCP(ms) | FCP(ms) | CLS | 폰트 요청 | 폰트 전송량 |
|---|---|---|---|---|---|
| 변경 전 (중앙값) | 13,667 | 12,613 | 0.000 | 3개 | 2,276KB |
| 변경 후 (중앙값) | 4,540 | 3,619 | 0.012 | 25개 | 297KB |

변경 전 3회: LCP 13,772 / 13,664 / 13,667ms.
변경 후 3회: LCP 2,882 / 4,540 / 4,672ms.

- CLS 0.012는 H1이 대체 폰트로 먼저 그려졌다가 Pretendard 조각이 도착하며 바뀐 것이다. 기준(0.1)보다 낮아 그대로 둔다. 줄이려면 `size-adjust`를 맞춘 대체 폰트 `@font-face`를 추가하면 된다.
- `fonts.css`는 200KB지만 brotli 9.3KB다. 굵기별로 같은 unicode-range가 반복돼 압축이 잘 된다.
- 쓰지 않던 Thin~Black 포함 전체 글리프 파일 9개(약 6.9MB)는 지웠다.
