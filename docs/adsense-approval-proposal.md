- 작성일: 2026-10-13
- 대상: https://seonghoho.com
- 근거: 저장소 코드, git 이력, 운영 중인 사이트의 실제 HTML/robots/sitemap/ads.txt 응답

## 0. 결론 먼저

**레이아웃이나 기술 설정 문제일 가능성은 낮습니다. 원인은 콘텐츠 쪽, 정확히는 "블로그로서의 신뢰 신호"가 약한 데 있습니다.**

기술 설정은 거의 다 맞게 되어 있습니다.

| 항목 | 상태 |
|---|---|
| `ads.txt` (`pub-6884620250599904`) | 정상 응답 |
| `google-adsense-account` 메타 태그 | 모든 페이지에 있음 |
| robots.txt / sitemap.xml (36개 URL) | 정상 |
| www → apex, http → https 리디렉션 | 정상 (301/308) |
| canonical | 페이지마다 정상 |
| 개인정보처리방침(`/privacy`), About | 있음 |

거절은 거의 항상 **"가치가 별로 없는 콘텐츠(Low value content)"** 에서 나오며, 이 사이트에서는 아래 네 가지가 겹쳐 그 판정을 받기 쉬운 상태입니다.

1. 게시일을 소급한 글을 한꺼번에 올림 (P0)
2. 색인 대상 글 25편 중 절반이 짧고, 주제가 겹치는 글이 많음 (P0)
3. 모든 글이 같은 템플릿 구조라 대량 생성 콘텐츠처럼 보임 (P1)
4. 사이트가 블로그가 아니라 포트폴리오로 보임 (P1)

> 거절 메일이나 AdSense 정책 센터에 적힌 **정확한 거절 사유 문구**를 알려주시면 진단을 좁힐 수 있습니다. "사이트 다운 또는 이용 불가" 같은 다른 사유라면 처방이 달라집니다.

## 1. 현황 진단 (수치)

### 1-1. 색인 대상 콘텐츠 규모

- 색인 대상 글: **25편** (`mordern-js-deep-dive` 4편은 이미 noindex)
- 주제 분포: SVG/Three.js 에디터 20편, Voca Study 5편. 사실상 한 프로젝트를 다룬 연재입니다.
- 본문 분량(코드 블록과 공백 제외 글자 수): **중앙값 약 1,600자**

| 분량 구간 | 글 수 | 해당 글 |
|---|---|---|
| ~1,100자 | 5 | voca-study 5편 전체 |
| 1,300~1,700자 | 8 | math-tool-*, pointer-keyboard, digital-math, canvas-experience, camera-state, selection-render-state, depth-render-order |
| 2,100자 이상 | 12 | 나머지 |

1,000자 남짓이면 화면 한두 개 분량이고, 코드 블록과 결론 불릿을 빼면 실제 설명은 더 적습니다. 심사 크롤러가 이런 글을 "얇은 콘텐츠"로 판정할 확률이 높습니다.

### 1-2. 게시일 소급 (가장 위험한 신호)

frontmatter의 `date`와 실제 최초 커밋일을 비교한 결과입니다.

| frontmatter `date` | 실제 추가일 | 글 수 |
|---|---|---|
| 2024-05 ~ 2025-09 | **2026-05-12 ~ 13** | **13편** |

- voca-study 5편은 `2024-05-02`부터 정확히 7일 간격으로 날짜가 찍혀 있습니다. 소급 배치의 전형적인 패턴입니다.
- Google은 URL을 처음 발견한 날짜를 따로 압니다. "2024년 글"을 2026년 5월에 처음 발견하면, 과거 콘텐츠를 지어내 사이트 이력을 부풀린 것으로 읽힙니다.
- 커밋 메시지 `feat(posts): add anonymized devlog articles`와 `fix(seo): tighten adsense review content signals`가 같은 날입니다. 심사를 앞두고 콘텐츠를 급히 채운 흐름이 그대로 드러납니다.

### 1-3. 템플릿 반복

- 전체 29편 중 **20편**이 `## 문제 상황` 으로 시작하고 `## 정리` + 불릿 요약으로 끝납니다.
- 문체, 문단 길이, 결론 형식이 거의 같습니다. 2024년 이후 Google은 이런 "규격화된 대량 콘텐츠(scaled content)"에 특히 엄격합니다. 사람이 쓴 글이어도 AI가 만든 글처럼 보이는 것 자체가 감점 요인입니다.

### 1-4. 주제가 겹치는 글 (서로 순위를 갉아먹음)

| 묶음 | 겹치는 글 |
|---|---|
| 렌더 순서 | `three-js-depth-render-order` ↔ `three-js-rendering-priority-debugging` |
| 오브젝트 선택 | `three-js-raycaster-hit-area` ↔ `three-js-object-selection-debugging` |
| 상태 분리 | `svg-selection-render-state` ↔ `svg-editor-state-boundary` |
| 에디터 구조 | `math-tool-interaction-rules` ↔ `math-tool-store-selection-flow` ↔ `pointer-keyboard-event-flow` |

25편이라는 숫자에 비해 서로 다른 주제는 15개 안팎입니다.

### 1-5. 사이트 정체성: 포트폴리오로 보임

- 홈 HTML의 실제 텍스트는 **약 1,260자**뿐이고, 3D 히어로와 카드 위주입니다.
- 헤더 순서가 `Home / About / Projects / Writing`이고, `docs/site-direction.md`에서도 우선순위를 `/projects` > `/posts`로 정해 두었습니다.
- 광고 허용 경로에 `/about`, `/projects/*`가 들어 있습니다. AdSense 관점에서 포트폴리오와 자기소개 페이지는 광고를 붙일 "게시자 콘텐츠"가 아닙니다.

심사자 입장에서는 개발자 포트폴리오에 글이 조금 붙어 있는 사이트로 보입니다. AdSense는 방문자가 반복해서 찾아올 콘텐츠 사이트를 승인합니다.

### 1-6. 자잘한 기술 이슈 (승인을 가르지는 않지만 정리할 것)

- **홈에 H1 없음:** 글 상세는 `stripLeadingH1Html`로 H1이 1개로 정리되어 있지만, 홈에는 H1이 아예 없습니다(히어로가 이미지뿐). 또 루트 layout의 `<main>` 안에 페이지별 `<main>`이 중첩되어 있습니다.
- **홈에 광고 스크립트 없음:** 홈 초기 HTML에 `adsbygoogle.js`가 들어 있지 않습니다. `next/script` + `afterInteractive`를 클라이언트 컴포넌트에서 쓰기 때문입니다. 메타 태그로 소유권 확인은 되지만, 심사 크롤러가 가장 먼저 보는 홈에 코드가 없는 상태입니다.
- **잦은 구조 변경:** 5/4, 5/12, 5/13, 5/22, 5/29, 7/1에 SEO/광고 관련 변경이 이어졌습니다. 심사 기간 중 URL, sitemap, noindex 정책이 계속 바뀌면 크롤러가 안정된 상태를 보지 못합니다.
- **대표 이미지 재사용:** 여러 글이 프로젝트 커버(`/images/projects/mathcanvas/cover-og.png`, `/images/portfolio/voca-study-1.png`)를 대표 이미지로 공유합니다.

## 3. 보완 액션 플랜 (6주)

### Week 0: 정리 (1~2일)

**A. 게시일을 바로잡습니다.**
- 소급된 13편의 `date`를 실제 공개일(2026-05-12 / 13)로 바꿉니다.
- 경험 시점은 본문 상단에 "작업 시기: 2024년 하반기 / 프로젝트: ○○" 처럼 따로 적습니다. 경험의 시간 정보는 살리면서 게시 이력은 사실대로 둡니다.
- 이번 한 번만 수정하고, 이후에는 날짜를 건드리지 않습니다.

**B. 얇은 글을 정리합니다.**
- **voca-study 5편**은 1편의 깊은 글로 합칩니다(예: "학습 플로우 상태 설계 회고"). 나머지 4개 URL은 301 리디렉션으로 넘깁니다.
- **겹치는 글**(1-4)은 묶음마다 강한 글 1편으로 합치고 301을 걸거나, 각 글의 관점이 확실히 갈리도록 다시 씁니다.
- 1,500자 미만인 글 중 살릴 글은 Week 1~2에 보강합니다. 살리지 않을 글은 noindex로 둡니다.
- `mordern-js-deep-dive`(책 요약)는 저작권 리스크도 있으니 사이트에서 내리는 쪽을 권합니다.

**C. 기술 정리.**
- 홈에 사이트 소개 H1과 소개 문단을 추가하고, 중첩된 `<main>`을 정리합니다.
- 광고 허용 경로를 **`/`와 `/posts/*`(색인 대상)** 로 줄입니다. `/about`, `/projects/*`는 뺍니다.
- 홈 초기 HTML에 `adsbygoogle.js`가 들어가도록 바꿉니다(예: 서버 컴포넌트 레이아웃의 `<head>`에 일반 `<script async>`로 넣기).

### Week 1~5: 신규 원본 글 10~12편 (주 2편)

목표는 **색인된 고유 글 30편 이상, 서로 다른 주제 20개 이상**입니다.

**글마다 지킬 기준**
- 본문(코드 제외) **2,500~4,000자**
- 직접 만든 **스크린샷, GIF, 측정값을 1개 이상** 넣습니다. 예: before/after 프레임 수치, 번들 크기, 재현 코드 링크
- 실패한 시도, 에러 로그, 버전 정보처럼 **나만 쓸 수 있는 디테일**을 넣습니다. 독창성 판정은 여기서 납니다.
- 구조는 글마다 다르게 씁니다. "문제 상황 → 정리" 틀을 벗어나 튜토리얼, 비교, 회고, 측정 리포트, Q&A 같은 형식을 섞습니다.
- 관련 글로 이어지는 내부 링크를 2개 이상 넣습니다.

**주제 다변화** (같은 프론트엔드 범위 안에서, 검색 수요가 있는 쪽)
- Next.js App Router 실무: 캐싱, 메타데이터, ISR 함정, 이 사이트를 만들며 겪은 Next 16 / Turbopack 이슈
- 성능: Core Web Vitals 개선 기록(Vercel Speed Insights 실측 데이터 활용)
- 캔버스 게임: `pixel-runner`, `space-shooter` 개발기를 제대로 된 글로 승격 (지금은 games 쪽에 noindex로 숨어 있음)
- 실무 회고: 에디터 제품의 설계 결정, 협업 방식, 코드 리뷰 기준

**발행 리듬:** 한꺼번에 올리지 말고 주 2회 정도 꾸준히 올립니다. 꾸준한 발행 간격 자체가 신뢰 신호가 됩니다.

### Week 1~3: 사이트 정체성 보강 (병행)

- **홈:** 최신 글 6~10개를 요약과 함께 위쪽에 둡니다. 목표는 홈 텍스트 3,000자 이상입니다. 3D 히어로는 아래로 내리거나 높이를 줄입니다.
- **헤더:** `Writing`을 맨 앞으로 옮깁니다(`Writing / Projects / About`). 라벨도 `Blog`나 `글`처럼 바로 이해되는 말이 낫습니다.
- **About:** 운영자 실명, 경력, 블로그에서 다루는 주제와 운영 원칙을 적습니다(E-E-A-T).
- **연락처:** `/contact` 페이지를 따로 만듭니다(이메일, GitHub). 지금은 푸터의 mailto뿐입니다.
- **카테고리 허브:** `categories/[category]`에 소개 문단 300자 이상을 넣고 색인 대상으로 올리는 것을 검토합니다. 지금은 noindex입니다.

## 4. 재신청 체크리스트

**콘텐츠**
- [ ] Search Console에서 **색인 완료된 글이 30편 이상**

**사이트**
- [ ] 홈에 글 목록과 요약이 충분히 보임 (텍스트 3,000자 이상)

**운영**

## 5. 하지 말아야 할 것

- **거절 직후 바로 재신청하지 않습니다.** 같은 상태로 다시 내면 같은 결과가 나오고, 반복 거절 기록만 쌓입니다.
- **날짜를 다시 소급하거나, 글을 대량으로 한 번에 올리지 않습니다.**
- **AI로 분량만 늘리지 않습니다.** 분량보다 나만 아는 디테일이 중요합니다.
- **심사 중에 사이트 구조를 바꾸지 않습니다.** URL, noindex 정책, sitemap은 신청 2주 전에 확정합니다.
- **광고 단위를 미리 많이 박아 두지 않습니다.** 심사 단계에서는 자동 광고 스크립트 하나면 충분합니다.
